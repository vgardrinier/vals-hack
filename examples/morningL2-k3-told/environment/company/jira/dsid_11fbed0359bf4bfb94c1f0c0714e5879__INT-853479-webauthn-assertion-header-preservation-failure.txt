WebAuthn device-assertion header mangled by ingress proxy causes SSO login loop for runbook-portal

Issue summary: Several on-call engineers report being unable to complete SSO login into the internal runbook-portal. Okta SSO returns success but runbook-portal displays 'authentication failed' and sends users back to Okta. This began after the 2026-03-11 ingress-api config rollout. Impact: Prevents access to runbook documentation for oncall; blocked incident responses; ~12 users affected in us-east. Observed behavior: After Okta auth, browser shows repeated redirect loop; network traces show app returning 401 with 'invalid device assertion'.

Post-department transfer caused loss of console role entitlements for multiple users

Issue summary:\nA set of users who completed a department transfer on 2026-03-11 lost assigned console roles (customer-Dedicated-admin, support-oncall) and no longer see Dedicated dashboards or internal billing views. This appears correlated with an HR-to-Okta sync that changed department attributes.\n\nImpact:\n- ~7 users in Prod (us-east) lost role-based access to Dedicated customer dashboards and some org-level console pages.\n- Affected users are primarily engineers and platform oncall; blocking day-to-day troubleshooting and incident response.\n\nEnvironment:\n- Prod | us-east, Redwood Console (SAML via Okta), SCIM provisioning pipeline from HR system to Okta.\n- Roles are granted via Okta group membership; groups are evaluated by mapping rules that depend on the Okta user attribute `department`.\n\nSteps to reproduce (observed):\n1) HR transfer event processed for user (hr_id 39872) on 2026-03-11 03:22 UTC.\n2) HR system pushed delta to SCIM provisioning service.\n3) Okta SCIM logs show a subsequent \"updateUser\" event where `department` was set to an empty string for the affected user.\n4) Okta Group Rules re-evaluated; user removed from several role groups (removeUserFromGroup events in Okta System Log).\n5) Console RBAC sync consumed Okta group change and removed console roles; users lost access.\n\nObserved logs/snippets:\n- Okta System Log (user: j.santos): `2026-03-11T03:23:14Z update_user department=\"\" ruleEvaluation=success`\n- SCIM provisioning: `200 OK - processed delta for user hr_id=39872; changes: department=null`\n- Console audit: `role_removal: user=j.santos roles=[customer-Dedicated-admin, support-oncall] origin=okta-sync`

Hypothesis: HR feed occasionally omits department for department-change cases, and our SCIM importer interprets missing field as explicit empty value and writes it into Okta, causing groups that depend on `department` to be removed.
Checked syncer service (svc-user-sync) logs: multiple entries show `patchUser` calls with payload `{"profile":{"department":""}}` instead of ignoring missing attribute.
No evidence of malicious activity; change aligned with scheduled daily HR delta at 03:20 UTC.

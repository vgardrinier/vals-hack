Insight panel metadata desynchronization after retention prune removes trace-context links and skews facet counts

Issue summary: BrightChat reports that after a scheduled retention prune completed on 2026-03-08, the 'Insight' panel for their org shows missing trace-context links on several rows and facet counts for 'region' and 'model' are lower than expected. Impact: Customers cannot navigate from panel rows to trace timelines, automated alert links point to 404, and several dashboards show undercounted usage for the last 30 days, causing billing/visibility concerns. Environment: prod, us-east primary ingestion, org: brightchat-prod, retention policy: org-default 30d compact/7d index-prune. Observed behavior: 1) Many insight rows have 'Trace link' column blank even when raw request IDs exist. 2) Facet counts in the panel summary are ~12-20% lower versus raw events export for same window. 3) Attempting to open links returns status page event 404 or link to a pruned index shard. Expected behavior: Trace-context links should resolve to trace timelines for any non-pruned detail within retention window; facet counts in panel should match raw events export for query window. Logs/attachments: Linked ingestion logs, sample raw-event export (attached to ticket), console screenshots showing blank links and count delta.
1) Use BrightChat org and open Insights > Custom > time range: 2026-02-09 to 2026-03-08. 2) Filter on event.type: inference.finish and model: redwood-v2-small. 3) Observe Insight panel rows: 'Trace link' column empty for ~18% of rows. 4) Export raw events for same filter and compare counts per region/model; exported counts are higher. 5) Click one of the blank trace links from UI and note 404 or 'trace not found' page.
Initial triage (Aisha 2026-03-09): Confirmed customer data exists in raw event store; links generated by console appear to reference trace IDs that were removed by a pruning job.
SRE note (Diego 2026-03-10): Retention prune job ran on 2026-03-08 02:14 UTC; job used index-prune-v2 which removed secondary index shards but did not update the console's insight-link index. Suspect stale link index not reconciled after compaction.
Hypothesis (Eng 2026-03-10): Two-phase prune removes searchable trace index before updating derived link table used by console; if link-table write fails (timeout/partial), links remain but point to pruned IDs.

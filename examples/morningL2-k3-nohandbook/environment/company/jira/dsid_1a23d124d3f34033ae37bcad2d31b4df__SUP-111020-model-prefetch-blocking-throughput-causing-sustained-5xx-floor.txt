Sustained 5xx error floor for Veridian Health during short-lived request fan-in — upstream runtime blocked by model-prefetch verification

Issue summary: Starting ~2026-03-14T03:10 UTC, Veridian Health reported persistent elevated 5xx responses (mostly 502/503) for a high-volume feature that issues many short-lived generate calls (avg 120ms). Impact: ~30% of requests returned 5xx over a 2-hour window; customer-facing product degraded. Environment: production, dedicated tenant on us-west pool, tenant pinned to a large quantized model. Initial hypothesis: api-gateway retries or connection churn. Further investigation pointed to upstream serving-runtime CPU and disk IO saturation caused by concurrent prefetch/verification tasks triggered by short-lived requests for a newly pinned model artifact.
1) Tenant pinned to redwood/llama-3-70b-quant via Console. 2) Issue a high QPS of short requests (payloads ~80 tokens, per-request latency target low) with many concurrent connections that connect/disconnect per request. 3) Observe api-gateway 502/503 rates increase and backend runtimes exhibiting high system CPU and many prefetch worker processes kicking off model artifact verification. 4) Reproduce in prod-us-west with customer workload simulator at ~350 req/s.

- Timeline: Customer traffic ramp at 03:08; error floor begins 03:10.
- Symptoms: api-gateway returned 502/503, upstream runtime returned 500/exit at times. Runtimes showed high system CPU and IO wait; many short-lived verifier processes were observed.
- Root cause hypothesis: Concurrent short-lived connections for a tenant pinned to a large model cause the prefetch/verification subsystem to be invoked more frequently than intended. Verification uses CPU and disk IO; when multiple verifier jobs overlap they starve request-serving threads and cause request timeouts.
- Why this surfaced now: Veridian pinned a large quantized model last deploy; a recent change (serving-runtime PR 4281) increased aggressive on-demand verification concurrency for safety, which under bursty short-lived workloads can trip the runtime's CPU/IO limits.
- Evidence: correlation between prefetch_worker start events and 5xx spikes; increased iowait and verifier process counts; PR 4281 introduced new quick-verification path that spawns verifier processes without global concurrency gate.
- Impact scope: primarily Veridian (enterprise tenant) on us-west pool, but similar tenants could hit if pinned to same model and issuing many short-lived requests.

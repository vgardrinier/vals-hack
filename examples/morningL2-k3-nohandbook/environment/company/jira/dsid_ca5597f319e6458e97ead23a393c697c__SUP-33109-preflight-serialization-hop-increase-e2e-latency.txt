Preflight schema serialization hop adding extra RPC and increasing E2E latency for function calls

Issue summary:\nCustomer reports a ~50-250ms increase in end-to-end latency for requests using function/tool calling after a runtime change that introduced a preflight schema serialization/validation hop. This appears to affect only requests that include tool schemas and function signatures.\n\nImpact:\n- End-user API latency increased (median +60ms, 95th +180ms) for function-enabled routes for the GloboCommerce account (dedicated pool).\n- Customer-facing pages load slower for chatbot flows that call external tools; some timed out after 1.5s.\n- Regression began after a canary rollout of schema-validator v1.4.0 on 2026-03-09.\n\nEnvironment:\n- Prod, us-east, Dedicated pool #GCU-42\n- API: POST /v1/chat/completions with \"functions\" schema present\n- SDK: redwood-js v0.9.16 (customer-integrated)\n\nSteps to reproduce:\n1) Send a chat completion request that includes a tool definition and function schema.\n2) Observe higher request latency compared to identical request without functions.\n3) Capture trace (X-Trace-Id header) and inspect spans between api-gateway -> schema-validator -> function-proxy -> serving-runtime.\n\nObserved logs / traces (examples):\n- Trace ID: trc_20260310_7f9a3b; total server time 410ms; span breakdown: api-gateway 18ms, schema-validator RPC 130ms, function-proxy 9ms, serving-runtime 240ms. Schema-validator shows multiple blocking calls to serialization routine and an auth handshake to function-proxy.\n- Datadog traces show schema-validator had a 2-hop RPC: -> schema-serializer -> signature-normalizer -> back. Each hop ~40-70ms.\n\nInitial hypothesis:\n- v1.4.0 of schema-validator introduced synchronous schema normalization and a cross-service handshake to verify tool signatures which causes additional RPC hops on the hot path.\n- No batching/caching for repeated schema hashes; every request with a schema triggers the full synchronous path.\n\nInvestigation notes (timeline):\n- 2026-03-10 09:12 UTC: Customer opened ticket reporting latency spikes after deployment.\n- 2026-03-10 09:30 UTC: Support captured sample traces and escalated to SRE/Runtime team (Slack #support -> #sre-runtime thread).\n- 2026-03-10 11:00 UTC: SRE confirmed elevated RPC counts from api-gateway to schema-validator for function-enabled requests (metrics: rpc_per_request increased from 1.02 to 1.98).\n- 2026-03-10 14:25 UTC: Runtime engineer reproduced locally by deploying schema-validator v1.4.0 and measured avg extra latency ~85ms per request.\n- 2026-03-11 02:10 UTC: Temporary mitigation tested: enable local LRU cache keyed by schema hash in api-gateway, avoiding round trip for repeated schemas. Measured reduction in median extra-latency to ~18ms for cached flows.\n\nRoot cause (current understanding):\n- v1.4.0 implements a synchronous, canonical serialization + signature verification step that lives in the schema-validator service. It performs a call to a normalization microservice for backward-compat checks. That normalization call is on the hot path and is not cached. For customers with repetitive tool schemas (common for SDK-driven product integrations), this adds an entire RPC hop per request.\n\nWorkaround / customer guidance:\n- For affected customers on Dedicated: set request field \"tool_validation\": \"off\" (temporary flag supported by gateway) to bypass preflight validation for known-good schemas. Note: this reduces safety checks; use only with trusted schemas.\n- For immediate improvement without turning off validation: request that the customer upgrade to runtime client that caches schema hashes locally (redwood-js >= 0.9.18 suggested).\n\nPlanned remediation and timeline:\n- Short-term (2026-03-12): deploy LRU cache in api-gateway for schema hashes across prod us-east (mitigation rollout completed 2026-03-12 03:20 UTC).\n- Medium-term (2026-03-18): change schema-validator to async normalization path (fire-and-forget for known schemas) and introduce per-instance in-memory cache. PR: github.com/redwood-inference/runtime/pull/4271 (merged, staged).\n- Long-term: add integration test for schema-validator that asserts no more than one outbound RPC for canonical schemas and instrument a dashboard alert for rpc_per_request regression.\n\nFollow-ups / action items:\n- SRE: add Datadog monitor for api-gateway -> schema-validator RPC count per request (alert if >1.2 baseline).\n- Runtime: ship async normalization and add strict cold-start caching behavior.\n- Support/CS: notify GloboCommerce of mitigation and recommend SDK upgrade; schedule a postmortem with customer on 2026-03-20.\n

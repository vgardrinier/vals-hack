Intermittent GPU unavailability and autoscaler oscillation traced to tenant background checkpoint writer

Issue summary: Several customers routed through a specific dedicated GPU rack in us-west-2 experienced brief GPU unavailability (~30-90s) causing request failures and p99 latency spikes. Impact: Multiple tenants saw elevated 5xx rates and streaming disconnects; autoscaler reacted by creating new nodes then immediately scaling down, causing capacity oscillation and added latency.
1) Deploy a high-throughput streaming route for rw-large-7b on a dedicated pool in us-west-2.
2) Start a small helper process on a tenant job that performs frequent lightweight GPU-backed checkpoint snapshots (every ~45s) to local NVMe (simulates periodic model state export).
3) Observe GPU driver logs and scheduler events.
4) Reproduce at 60-75% pool utilization to increase chance of contention.
- kubelet: warn: 'device plugin reported GPU reset' at 2026-03-11T09:22:13Z
- nvidia-smi: 'GPU 1: Process table empty; device reset' around same timestamp
- autoscaler events: scale_up triggered by pending_pods at 09:22:20Z; scale_down executed at 09:23:55Z with reason 'insufficient capacity'
- Grafana panels: spike in 'gpu_unavailable_count' aligned with 5xx spike: https://grafana.redwood.io/d/GPUs/us-west-2-pool-heatmap
- k8s events: Pod eviction reason 'GPU_UNHEALTHY' (our internal label), transient host cordon for 95s

Timeline: 09:20-09:25Z correlated GPU resets with tenant checkpoint activity. Hypothesis: periodic GPU-backed checkpoint writer invoked a driver-level cleanup path that temporarily made the GPU unreachable to the kube device plugin, leading the scheduler to mark host as degraded and move pods. Evidence: dmesg showed repeated 'NVME_RESET' and 'nvidia: GPU watchdog triggered' messages tied to the same host. NVMe I/O spikes precede GPU resets. Autoscaler behavior: aggressive pending-pod threshold + no cooldown caused scale_up, then health checks recovered the host and scale_down ran, producing oscillation. Temporary mitigation validated: disabling checkpoint writer for that tenant removed the resets and stabilized P99 within 2 minutes.

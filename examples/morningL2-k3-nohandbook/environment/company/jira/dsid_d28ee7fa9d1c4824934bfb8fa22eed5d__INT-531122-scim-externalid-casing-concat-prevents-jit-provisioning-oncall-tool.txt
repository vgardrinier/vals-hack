JIT provisioning fails for contractors when SCIM externalId is mixed-case and suffixed — oncall role not assigned

Issue summary: Several contractor accounts are not getting the OnCall Runbook role during just-in-time (JIT) provisioning. Impact: ~12 contractors could not see/claim oncall shifts for the past 36 hours; blockers for rotation coverage and pager escalation. Environment: production, us-east region. Observed behavior: identity-service receives SCIM user create events but RBAC lookup does not match existing contractor mappings; result is user is created without oncall role. Expected behavior: JIT path should normalize SCIM externalId and apply the appropriate contractor role mapping so users can access OnCall Runbook and related tooling.
1) Create or update a SCIM user in Okta with externalId="MikeChen::Contractor" (mixed case + suffix).
2) Ensure SCIM user is in group 'contractors-oncall' during initial sync or JIT flow.
3) Trigger a login flow (SSO) for that user to cause JIT provisioning.
4) Observe identity-service logs and check OnCall Runbook console for role assignment — user appears without 'oncall-runbook' role and receives 403 when accessing runbook pages.

Initial triage by Support (S. Ortiz): problem began after bulk SCIM provisioning run on 2026-03-04 evening; sample affected accounts all have externalId values with mixed casing and a '::Contractor' suffix added by a downstream HR script.
Hypothesis A (Devon Li): JIT path was changed last quarter to do a strict equality lookup against stored externalId for RBAC mapping; it does not perform the same canonicalization used by the nightly SCIM reconciliation job.
Hypothesis B (Priya Nair): RBAC mapping also uses a 'canonical_external_id' index that was populated by a lowercasing pipeline which the JIT flow bypasses, causing misses for new JIT creations.
Partial finding: nightly reconciliation (scim-reconcile job) normalizes and strips suffixes when writing canonical IDs — JIT provisioning did not run that code path and therefore created accounts without the expected canonical key.

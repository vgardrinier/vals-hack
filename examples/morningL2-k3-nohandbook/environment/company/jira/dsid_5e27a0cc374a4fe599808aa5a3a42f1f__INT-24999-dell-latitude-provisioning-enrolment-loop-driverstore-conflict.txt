Dell Latitude 7440 provisioning hangs during post-enrolment when driverstore contains duplicate Broadcom NIC package

Issue summary: New hires' Dell Latitude 7440 devices consistently stall at the 'Completing device setup' stage immediately after Intune enrolment. Impact: Blocks first-login provisioning for ~20 new hires since 2026-03-08; requires manual intervention by IT imaging to complete setup. Environment: prod-us-west, standard corporate provisioning image (corp-win11-2026-02), Intune autopilot + SCCM hybrid co-management. Observed behaviour: device shows 'Provisioning stuck: Completing device setup' UI and Network driver does not initialize (no NIC). BitLocker auto-encrypt attempted but fails intermittently. No obvious SCCM task sequence errors; Intune shows device as Enrolled but Managed, and MDM enrollment logs show extended timeouts during device join.
1) Build Dell Latitude 7440 from imaging pool using corp-win11-2026-02 image. 2) Boot to OOBE and autopilot enroll to Intune. 3) Allow autopilot to run default provisioning (install corp apps, drivers via WinGet and Win10Drv packages). 4) Observe that after 'Completing device setup' the NIC remains in Device Manager with error code 31 or 28 and provisioning does not progress. 5) Manually inspect C:\Windows\INF and driver store. Note duplicate Broadcom NIC packages referenced in setupapi logs.
